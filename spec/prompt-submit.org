- =unlink()= (517): replaced with =wp_delete_file()=. Before WP 6.4

  =file_exists()= afterward. This works with your "Requires at least:
  6.0".
- =rmdir()= (568): now uses =$wp_filesystem->rmdir($path,
  false)=. Because it isn't recursive, it only removes empty folders,
  same as before. If =WP_Filesystem()= can't start, pruning is skipped
  and returns 0.
- Nonce warnings (579, 582, 653, 655):
  - All =$_POST= reads now happen inside =tmcc_fHandlePost()=, after =check_admin_referer()=.
  - I removed the =tmcc_fPostText()= helper, since that change left it
    unused.
  - The render page no longer re-reads =$_POST=. It reads the saved
    option, which the handler has just updated with the same values.
- Direct DB query (103): the slug lookup now uses =get_posts()= with
  =name=, which is cached, limited to post/page, and uses the same
  status list as the rest of the plugin. This also fixes a bug:
  non-ASCII slugs are stored percent-encoded, so the old
  =rawurldecode()= + raw SQL compare could never match
  them. =get_posts= re-encodes the slug the way WordPress stores it.
